# 用户管理中的应用记录

统一账号可以关联多个应用。用户列表按所选应用的有记录/暂无记录筛选，支持账号、邮箱、昵称搜索；计数与分页使用相同条件。用户明细逐项显示所有已登记应用，包括停用应用。

## 来源与登录记录

- 注册来源：邮箱注册、微信首次建号、管理员创建分别记录方式与来源应用。直接注册显示账号中心。已存在的微信账号再次登录、账号绑定微信，不改写原注册来源。
- 邮箱注册使用浏览器绑定且经过 OAuth 校验的请求传递来源，不从 Referer、任意 client_id 或应用名称推断。注册后生成新的同应用登录请求，保留原回调、state、nonce 和 PKCE，继续要求用户登录。
- 完成授权：账号中心已完成认证并签发授权码。此状态不代表业务应用已收到回调。
- 已签发登录凭证：应用成功换取过令牌。此状态不代表业务应用已落库创建或同步账号。
- 暂无登录记录：当前没有留存证据，历史数据可能已被清理，不能断定从未登录。
- 历史来源未记录：新功能之前创建、没有来源元数据的账号。不会用首次应用登录猜测注册来源。

## 数据与更新兼容

沿用现有 users、clients、auth_codes、access_tokens、audit_events 表，database/schema.sql 不变。注册来源写入 user.registration-source；每个用户/应用的首次授权、首次凭证签发分别记录 application.first-authorized、application.first-token。

来源写入与账号创建共用事务。首次应用记录写入与授权/令牌签发共用事务，并在已有用户行锁内查询；重复签发不会持续增加首次记录。查询对历史凭据和持久记录聚合，避免一人多个令牌造成重复用户。

bin/console cleanup 在删除过期凭据前，先将仍留存的历史授权/令牌证据补为首次应用记录，重复运行不会持续增加同一记录；然后清理过期凭据与普通日志，保留上述三类持久元数据。原来已经被清理的记录无法恢复。最近留存记录不是完整的最后一次业务平台登录时间。平台未接入回报接口，因此没有展示真实同步状态。

管理员权限保护用户列表和应用明细；普通账号与匿名访问分别拒绝。筛选字段使用参数绑定；动态应用名称、来源、用户信息继续经 HTML 转义。

## 本地验证

tests/admin_users.php 覆盖来源保护、应用正反筛选、注册与登录区分、过期凭据删除后的记录保留、分页计数与稳定排序。tests/integration_http.py 覆盖权限、浏览器绑定的应用注册、原回调保持和原有认证/扫码/并发流程。tests/run.php 回归认证核心。
