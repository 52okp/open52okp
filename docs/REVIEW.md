# PHP 重构审查与验证记录

日期：2026-10-08。范围为本目录 PHP 版本及与已发布小程序的接口衔接。Java 原有审查记录仍保留在仓库根目录 docs/CODE-AUDIT-20261004.md；本次部署不加载原 Java 代码。

## 技术方案

PHP 8.2+、Slim 4、League OAuth2 Server、Lcobucci JWT、PHPMailer、OTPHP、PDO MySQL。OAuth 授权码和 PKCE、加密授权码/刷新令牌使用已有库；应用仓储负责数据库锁、一次性兑换、状态和撤销检查。模板与静态资源保存在项目内，无外部字体、JS CDN 或前端构建依赖。

MySQL 表采用 InnoDB、utf8mb4、普通 TEXT/索引字段，不使用 MySQL 8 专用语法。验证环境是实际 MySQL 5.7.44，不是 SQLite 替代测试。

## 审查中处理的问题

| 场景 | 处理 |
| --- | --- |
| 登录码请求反复触发微信 API | 微信 stable_token 加锁缓存；每张 ticket 的图片只生成后缓存，前端独立轮询状态 |
| 图片失败仍显示空白码 | 显示错误信息、有限重试和手动刷新；无效图片不作为成功返回 |
| 已过期 ticket 无法刷新 | 原浏览器可刷新过期请求，新 ticket 替换旧 ticket，不能复活已消费请求 |
| 二维码转移或重复消费 | 浏览器绑定摘要、独立图片 key、手机 wx.login 校验、数据库行锁、单次消费 |
| 同一微信重复创建/强行合并账号 | 唯一键与事务串行化；拒绝覆盖其他账号的绑定 |
| 授权码/刷新令牌并发兑换 | MySQL 行锁；授权码一次性；刷新轮换并检测重放，重放撤销用户在该客户端的凭证 |
| 验证码错误次数回滚 | 失败返回事务结果，让计数提交；最多 5 次且绑定用途/邮箱/浏览器 |
| 动态验证码重复使用 | 保存最后接受的时间步；恢复码 HMAC 摘要、事务消费 |
| 改密码/禁用账号后旧凭证仍可在线使用 | session_version + 数据库撤销检查；UserInfo 和自省立即检查 |
| 安全配置修改与旧身份验证并发 | 锁定用户并比对会话版本，再修改或签发；客户端校验与配置更新也串行化 |
| ID Token at_hash 不一致 | 同一 access_token 实体只序列化一次，at_hash 对最终令牌计算 |
| 访问令牌到期导致有效 refresh 自省错误 | 分别校验两种凭证，刷新受原始验证后 8 小时上限约束 |
| CSRF、XSS、参数重复和回调跳转 | Web POST 验证 CSRF；输出转义；重复/数组参数拒绝；精确 HTTPS 回调；安全响应头 |
| 误信任伪造代理头 | APP_URL 固定；应用只用 REMOTE_ADDR，EdgeOne 真实 IP 在可信 Nginx 配置恢复 |
| 部署泄露配置/私钥 | Web 根目录只用 public；配置与存储在外；包不带 .env、密钥、会话或日志 |

## 功能边界

本版本实现单 Realm 的核心 OIDC 登录接口，并非 Keycloak 功能等价替代。没有 SAML、Keycloak 管理 API、组织/复杂角色体系、跨站后台登出、网页自助注销/解绑/更换已验证邮箱。后台支持账号启停，不直接改密码或查看用户密码。业务权限仍由业务网站管理。

离线验证 JWT 的业务站无法立即看到服务器侧撤销，应使用 UserInfo/自省或短期本地会话。源码已清楚区分该限制，不能宣传“关闭账号后所有业务站本地会话马上退出”。

MySQL 5.7 按需求兼容；生产数据库的备份、访问限制及平台维护由部署方负责。全新初始化不会保留原 Java 测试用户或原客户端密钥。
